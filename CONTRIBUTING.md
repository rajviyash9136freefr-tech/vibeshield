# Contributing to VibeShield 🛡️

First off, thank you for considering contributing to VibeShield! Whether you're reporting a bug found during vibe coding, adding rules for hallucinated packages, or improving agent skills, you are warmly welcome here.

---

## 🌟 How You Can Contribute

1. **Add Bug Hunter Rules**:
   - VibeShield rules live in [`rules/core/`](rules/core/) in simple YAML format.
   - Found an LLM hallucinating a non-existent package or scaffolding dangerous boilerplate? Submit a YAML rule with golden test fixtures.
   - After editing, run `node scripts/sync-rules.mjs` — the scanner embeds a copy of the packs and CI fails if the two drift.

2. **Improve AI Agent Integrations**:
   - The shared rule block lives in one place: `AgentRulesBody` in [`scanner/internal/cli/catalog.go`](scanner/internal/cli/catalog.go).
   - Edit it there, then run `node scripts/sync-agent-rules.mjs` to regenerate all seven agent files (`AGENTS.md`, `.agents/rules/`, `.cursor/rules/`, `.cursorrules`, `.windsurf/rules/`, `.windsurfrules`, `.github/copilot-instructions.md`). See [docs/agents.md](docs/agents.md).
   - Never hand-edit a generated agent file — `--check` will fail CI.

3. **Report AI Coding Bugs & False Positives**:
   - [Open an Issue](https://github.com/rajviyash9136freefr-tech/vibeshield/issues) with the code sample generated by your AI agent and the unexpected behavior.

4. **Enhance the Web Simulator & Documentation**:
   - The documentation and interactive simulator live in [`site/`](site/) built with Astro 5 and Tailwind CSS v4.

## 💻 Local Development

### Scanner engine (Go 1.24+)

```bash
cd scanner
go test ./...
go vet ./...
go build -o vibeshield ./cmd/vibeshield
```

Then try the v2 console and the search index:

```bash
./vibeshield                 # interactive console (needs a real terminal)
./vibeshield search aws      # the same ranking, scriptable
./vibeshield agents --body   # the shared agent rule block
```

### Documentation & website (Astro)

```bash
cd site
npm install
npm run dev
```

## ✅ Definition of done

A change is ready when:

- `cd scanner && go test ./... && go vet ./...` is clean.
- `node scripts/sync-rules.mjs --check` is clean (rule packs in sync).
- `node scripts/sync-agent-rules.mjs --check` is clean (agent files in sync).
- `gofmt -l` reports nothing for the files you touched.
- New exported behaviour in Go has a `_test.go` covering it — see
  [`scanner/internal/cli/search_test.go`](scanner/internal/cli/search_test.go)
  for the table-driven style used for the search ranker.
- It builds for every release target:
  `GOOS=linux GOARCH=arm64 go build ./...` and the same for `darwin/arm64`,
  `windows/amd64`. Raw-terminal code lives in `term_{windows,linux,darwin}.go`
  and must keep compiling per platform.
