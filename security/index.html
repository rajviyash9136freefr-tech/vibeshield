Trust

Security & threat model

What leaves your machine

  • CLI & pre-commit hook: nothing. Static analysis is fully local; the rules engine runs from the embedded pack. Network calls happen only with explicit --online, and then only package names go to public registries — never file contents.
  • GitHub Action: analysis runs on your runner. We send findings metadata to the dashboard — file paths, rule IDs, symbol names, severities. File contents and snippets are never persisted server-side; snippets exist only inside your PR comment.
  • Private-repo results are never used for model training. Ever.

Trust boundaries

Component Runs Handles
scanner (Go binary)your machine / runnersource files (read-only), git metadata

package-intel APIour cloudregistry snapshots (npm/PyPI/crates/Go); sees package names from opt-in --online lookups
findings API + dashboardour cloudfindings metadata; GitHub OAuth; no file contents

How the scanner reads your code

  • Read-only file access; the scanner never writes to your repo (init writes config files, and says so first).
  • It does not execute your code, install dependencies, or build. Findings are pattern matches over text, weighted by AI-likelihood.
  • Secrets found in matched lines are redacted by the scanner (4 + 4 characters kept) before anything is printed, posted, or sent.

Disclosure

Found a vulnerability in VibeShield itself? Email security@vibeshield.dev — PGP key on request. We acknowledge within 48 hours and aim to ship a fix within 14 days for anything rated high or above. Please don't open a public issue first; we'll credit reporters who give us the window.

Precision, honestly stated

No scanner is right all the time. Our release bar is ≥ 85 % precision on critical/high findings against a 200-PR golden set, ≤ 5 false positives per 1k diff lines, and every dismiss carries a required reason into an audit log we can learn from. When a rule underperforms we lower its confidence or retire it — the pack's changelog is public in the repo.
