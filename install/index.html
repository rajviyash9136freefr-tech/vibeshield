01 · Zero install

first run ~30 s · every run after it under 2 s

npx vibeshield scan .

02 · The direct command

One line, then it is just installed

The installer drops the static binary in ~/.local/bin, checks it against the release sha256sums, and — if it spots one — wires the audit skill into your coding agent. Linux, macOS, and Git Bash on Windows.

no sudo · no PATH edits behind your back · --agent none to skip the skill

terminal 
curl -fsSL https://raw.githubusercontent.com/rajviyash9136freefr-tech/vibeshield/main/scripts/install.sh | bash

03 · The gate

Five lines of YAML, every PR covered

Drop the file, push the branch, forget about it. From the next pull request on, the VibeCheck report posts itself — in warn mode by default, so it informs before it ever blocks.

runs on your runner · code never leaves it

.github/workflows/vibeshield.yml 
name: VibeShield
on: [pull_request]
jobs:
  vibeshield:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: rajviyash9136freefr-tech/vibeshield/action@v3.0.0

The first sixty seconds, honestly

Here is exactly what happens when you run the command above in a repo with AI-written code in it. Nothing is phoned home, nothing is installed that you did not ask for, and the scan finishes before your coffee lands.

  • 1.The binary is fetched and its sha256 is checked against the release manifest. A mismatch refuses to run — loudly.
  • 2.The rules pack (core 2.0.0, MIT) loads from inside the binary. Zero network, zero config.
  • 3.Every tracked file gets pattern-matched against the 122 AI-failure-mode rules — 117 of which the engine can evaluate today.
  • 4.Findings print in the VibeCheck format: why it matters for AI code, the pattern, a one-line fix. Secrets are redacted to 4+4 characters before anything is printed.

What can actually go wrong

Four honest answers to the four things that actually stop an install. If yours is not here, open an issue — someone reads them.

I am on Windows. Does the one-liner work?

+

Use the PowerShell installer (irm … | iex), which downloads vibeshield-windows-x86_64.zip, unpacks vibeshield.exe into ~/.local/bin, adds it to your user PATH, and wires the audit skill into any coding agent it finds. The .sh installer is for POSIX shells — Git Bash works, plain PowerShell does not.

Corporate proxy / air-gapped network?

+

Download the archive for your platform from GitHub Releases, check it against the matching line in sha256sums.txt from the same release, and put the binary on PATH. Rules are embedded in the binary, so scans work with the network unplugged — the scanner links in no HTTP client at all.

I ran it and nothing printed but findings.

+

Good. Exit code 0 means the scan completed; in the default warn mode findings never fail the run. In CI, set mode: block-on-critical in vibeshield.yml when you want the check to gate merges — the docs page walks through the four modes.

How do I get rid of it?

+

rm ~/.local/bin/vibeshield (or delete vibeshield.exe), remove the workflow file, remove the hook entry, and delete vibeshield.yml. There is no daemon, no service, and no state outside your repo to clean up.

I am not sure it is installed correctly.

+

Run vibeshield doctor. It reports the binary and its rule pack, the config, the git hook, the PR-gate workflow and your agent rule files, and prints the exact command that fixes each gap. It changes nothing, and it exits 1 when something needs fixing.
